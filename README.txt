Xiaomi 14 MiFi Web Control v1.5.20
==================================

适用环境：
- 小米14（houji）
- HyperOS 3 / Android 16
- KernelSU ROOT

安装：
1. 先停止 Termux 临时网页服务（Ctrl+C），避免占用8080端口。
2. KernelSU 管理器 → 模块 → 从本地安装本 ZIP。
3. 重启手机。
4. 连接热点 Xiaomi14-MiFi，密码 87654321。
5. 优先访问固定地址 http://192.168.43.1:8080。
6. 如果固定地址在当前ROM不可达，在客户端 Wi-Fi 详情中查看“路由器/网关”地址，然后访问 http://网关地址:8080。
7. 默认网页登录：admin / admin。
8. 首次登录后立即进入“后台安全”修改管理密码。

默认设置：
- SSID：Xiaomi14-MiFi
- Wi-Fi 密码：87654321
- 频段：2.4GHz
- 开机自动启动：开启
- Web端口：8080

v1.3.6 新增功能（P0+P1 批次 14 项）
---------------
一、日志与稳定性
1. 服务日志自动轮转：超过 512KB 自动截断保留最近 400 行，长期运行不再撑爆 /data。
2. 操作锁 trap 释放：热点启停等后台操作即使异常退出也会自动释放操作锁，
   不再残留 120 秒的“已有操作正在执行”。

二、设备识别与管控
3. 客户端厂商识别：设备列表按 MAC 前缀（OUI 表，12 家主流厂商）显示品牌，
   如 Apple / 小米 / 华为 / 三星 / OPPO / vivo / 荣耀 / Google / 联想 / 摩托罗拉 / 华硕 / Intel。
4. 一键踢下线：临时断开指定设备（15 秒内无法重连），区别于黑名单的永久拉黑；
   已在黑名单中的设备不会被误解除。
5. 新设备接入提醒：首次出现的设备 MAC 自动写入日志（含 IP、MAC、厂商），
   配合厂商识别方便发现陌生设备接入。

三、流量管理
6. 蜂窝流量统计：系统状态卡显示手机 4G/5G 本次开机累计上下行（/proc/net/dev rmnet 计数）。
7. 流量限额自动关热点：设置 MB 上限，累计蜂窝流量超过后自动关闭热点并写日志，
   防止超流量扣费；限额数据持久化，热点重启不清零。支持一键重置累计。

四、定时增强
8. 定时多组：定时模式支持 每天 / 工作日（周一至五）/ 周末（周六日），
   工作日与周末可设不同开关时间；非运行日当天不会自动开启。
   说明：定时检测基于 15 秒轮询，到点执行最多延迟约 15 秒（P2-23，接受该粒度）。

五、后台与运维
9. 密码查看：热点设置卡“显示当前密码”按钮（需登录+令牌），8 秒后自动隐藏。
10. 端口设置：后台安全卡可修改 Web 端口（1024–65535），2 秒后自动切换。
11. 重启模块按钮：一键重启 httpd + watchdog，无需 SSH。
12. 电池信息缓存：15 秒缓存，减少每 5 秒轮询的 dumpsys 开销。
13. 空闲关闭倒计时预告：空闲自关前页面顶部黄色提示“距空闲自动关闭还有 N 分钟”。

已知限制（HyperOS 固有，无法通过模块修复）
------------------------------------------
- 网页修改热点名称/密码仅临时生效，系统设置页不保存；在手机系统设置手动开关热点后会恢复旧 SSID/密码。请始终使用本网页开/关热点。
- 单 Wi-Fi 硬件不能 STA+AP 并发；普通 Wi-Fi 开启时热点可保持运行，但上游联网是否可共享给客户端取决于 HyperOS 路由策略（页面有检测提示）。
- 定时/保活/空闲关闭由模块 watchdog 每15秒轮询驱动，误差在15秒以内。
- 流量限额口径为手机蜂窝接口累计流量（本次开机起），与运营商账单口径可能有差异，仅供参考。

v1.3.4 修复（真机反馈）
---------------
1. 修复：已连接设备数量始终显示 0 / 设备列表为空。原因：客户端发现只依赖
   `ip neigh`，而设备刚连上热点或处于省电状态时该邻居表可能暂时为空。
   现改为双数据源合并：优先读取 /proc/net/arp（设备完成 DHCP 后必有条目，
   最可靠），再用 ip neigh 补充实时状态（在线/待机），按 IP 去重；
   空闲自动关闭的客户端计数同步改用该数据源，判断更准。
   诊断报告新增 arpRaw / neighRaw / clientList 原始数据，便于定位。
2. 修复：诊断报告“复制报告”按钮在手机浏览器上无反应。原因：管理页是
   http://IP 非安全上下文，浏览器不提供 navigator.clipboard 接口。
   现增加 execCommand 复制兜底（兼容安卓自带浏览器/微信/QQ 内置浏览器），
   兜底也失败时提示长按文本手动选择复制。
3. 修复：暗色模式下所有边框（卡片、输入框、按钮、分割线、焦点高亮）颜色过亮、
   刺眼。统一改为暗色专用低对比色：卡片边框、分割线、输入框边框全部调深，
   输入框获得焦点时的亮蓝高亮也改为暗色蓝。深色下视觉不再发白。

v1.3.3 修复（二维码功能）
---------------
1. 修复：热点二维码功能不成功。原因有两处：
   a. 点“显示热点二维码”时若密码框为空（模块出于安全不回传已保存的密码），
      旧版只是静默提示、不生成二维码，容易误以为功能失效。

      静态 .js 文件分发；并增加明确错误提示（库缺失/生成失败都会显示原因）。

v1.3.2 修复（真机反馈）
---------------
1. 修复：系统状态卡“运营商/数据”显示整段原始 dumpsys 文本、数据连接一直显示“未连接”。原因：真机 dumpsys telephony.registry 的各字段在同行逗号分隔，旧解析会把整行剩余内容当作运营商名，数据连接数字也被行内其他数字污染。现已按字段精确截断（取到逗号前），运营商显示“中国移动”、数据连接正常显示“已连接/未连接”。
2. 修复：暗色模式下输入框、日志/诊断区、提示框、徽章、按钮文字看不清（背景写死浅色、文字随主题变亮的亮字浅底）。已全部改为主题变量，对比度 ≥6.8:1。
3. 修复：每客户端流量统计的规则维护函数从未被调用，统计链内没有按 IP 计数的 RETURN 规则，流量恒显示 0；现状态轮询时自动维护统计规则。
4. 修复：客户端“上传/下载”显示语义颠倒（rx 显示成了上行）。现 rx=下载、tx=上传，与页面 ↑/↓ 标识一致。

- 已连接设备显示 上传/下载 字节数（FORWARD 统计链，重启后清零）。

四、系统与 SIM 状态
- 页面“系统状态”显示：运营商/数据连接、信号强度、内存、存储、负载、温度、运行时长。

五、日志与诊断
- “查看日志”读取服务日志（最多200行）。
- “生成诊断报告”一次性汇总：热点接口/IP/固定别名、保活与定时配置、网络共享检测、httpd 进程、CSRF、SELinux、iptables 摘要、日志尾部，可直接复制提交排障。

六、定时与自动
- 热点保活开关：开启时热点意外掉线自动拉起；关闭时不会自动重启。
- 空闲自动关闭：连续 N 分钟无在线客户端自动关闭热点（0=关闭该功能）。
- 定时开关：每天指定时间自动开/关热点（开启后覆盖手动状态；非窗口期不自动拉起）。

七、配置导入导出
- “导出配置”下载当前全部设置（conf 文本）。
- “导入配置”上传后校验并生效；非法键值自动忽略并修正。

八、热点设置增强
- 信道选择（0=自动；2.4G/5G 按频段列出常用信道）。
- 最大连接数限制（0=不限），下次重启热点时生效。

九、其他
- 深色/浅色主题切换（记住选择）。
- 管理页继续同时显示“固定管理地址”与“备用网关地址”。

已知限制（HyperOS 固有，无法通过模块修复）
------------------------------------------
- 网页修改热点名称/密码仅临时生效，系统设置页不保存；在手机系统设置手动开关热点后会恢复旧 SSID/密码。请始终使用本网页开/关热点。
- 单 Wi-Fi 硬件不能 STA+AP 并发；普通 Wi-Fi 开启时热点可保持运行，但上游联网是否可共享给客户端取决于 HyperOS 路由策略（页面有检测提示）。
- 定时/保活/空闲关闭由模块 watchdog 每15秒轮询驱动，误差在15秒以内。
- 流量统计基于 iptables FORWARD 链，重启后清零；仅统计经热点转发的流量。

安全说明
--------
- 控制接口使用登录认证 + 防伪令牌 + 操作互斥锁 + 输入校验，不提供任意 Root 命令接口。
- 状态接口不回传已保存的热点密码；密码框留空表示保持原密码。
- 配置文件与日志权限 0600，仅 root 可读。

排障
----
- 页面打不开：检查 8080 是否被 Termux/其他服务占用；关闭系统电池限制防止后台被杀。
- 按钮无反应：确认 KernelSU 已授予本模块 SU 权限；Termux 里先验证：
    su -c 'cmd wifi start-softap test wpa2 87654321 -b2'
- 5G 热点无法启动：把频段改为 2.4GHz，或手动指定信道再试。
- 客户端连上但无法上网：查看“网络共享”卡片判断；可用“生成诊断报告”把结果发出来排查。
