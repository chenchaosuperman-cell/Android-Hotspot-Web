# Android-Hotspot-Web

面向已 Root 安卓设备的本地热点管理模块，当前主要在小米/Redmi 设备上测试。

本项目通过 KernelSU 模块在手机本地运行轻量 Web 管理后台，允许连接热点的设备查看状态、开关热点、修改热点参数、管理客户端、统计流量并配置自动化、消息通知与透明代理。

> 当前主要在 Xiaomi 14 / HyperOS 3 / Android 16 / KernelSU 上完成测试；其他设备通过动态能力检测运行，未验证机型标记为 Experimental。

## 功能

### 热点控制
- 一键开启、关闭热点
- 手动关闭后，本次开机不再被保活或定时任务自动拉起
- 重启手机后按照"开机自动启动"设置执行
- 关闭热点不停止短信转发和消息通知
- 修改热点名称、密码、加密方式、频段、信道
- 隐藏 SSID（不广播热点名称，需手动输入名称和密码连接；仅隐藏名称广播，不是安全机制；保存前自动检测系统是否支持 -h，不支持则禁用开关，启动失败自动回滚为广播）
- 设置最大连接设备数
- 显示实际运行状态与已保存配置
- 热点异常掉线自动恢复
- 启动失败和自动恢复通知

### 自动化
- 开机自动启动热点
- 热点异常保活
- 空闲无客户端自动关闭
- 每天、工作日、周末定时开关
- 支持跨午夜定时
- 手动关闭与自动策略状态区分
- 显示最近一次策略关闭原因

### 流量管理
- 今日热点流量
- 本月热点流量
- 当前账期用量
- 套餐总量、剩余流量和使用百分比
- 自定义账期起始日
- 最近多日流量图表
- 历史账期记录
- 自定义流量提醒节点
- 流量耗尽预测（按当前日均消耗估算剩余可用天数）
- 超额仅提醒或自动关闭热点
- 重置流量累计

> 流量统计仅计算热点客户端的转发流量，不包含手机自身使用的移动数据。统计结果可能与运营商账单存在差异。

### 设备管理
- 查看当前连接设备
- 显示 IP、MAC、厂商及在线状态
- 历史设备记录
- 添加设备备注
- 禁止或恢复设备上网
- MAC 访问控制双模式：黑名单 / 白名单（仅允许名单内设备上网）
- 临时断网
- 实验性设备限速
- 清空名单

> 设备限速为实验性功能，不同内核和 ROM 的 tc 支持可能不同；系统无 tc 时该入口自动隐藏。

### 消息通知
- PushPlus 微信通知
- 钉钉群机器人通知（支持加签）
- Bark（iPhone 推送）
- 自定义流量提醒节点
- 低电量提醒
- 热点启动失败通知
- 热点自动恢复通知
- 短信转发到 PushPlus、钉钉或 Bark
- 通知渠道健康状态
- 失败重试和待发送队列
- 测试通知功能

### 科学上网（Mihomo）
- 安装时自动下载 Mihomo ARM64 核心（v1.19.31），多镜像 fallback
- 支持 Clash/Mihomo 订阅、AUTO 自动选择、FALLBACK 故障转移、MANUAL 手动选节点
- 热点客户端 TCP/DNS 透明代理，国内 IP 直连、其它流量按代理策略处理
- 节点测速、订阅更新、节点健康检查和异常自动恢复
- 代理范围（仅热点设备 / 仅手机本机 / 两者）在「高级设置」中调整；默认仅代理热点设备，不影响手机自身联网
- 本机代理与热点客户端代理使用独立 iptables 链，可单独启停，互不影响

> 当前透明代理仍以 REDIRECT/TCP 为主；UDP/443 默认通过阻止 QUIC 促使应用回落到 TCP。完整 UDP/TPROXY 尚未作为默认模式。

### 管理与诊断
- 局域网 Web 管理
- 亮色、暗色主题
- 手机端响应式布局
- 修改后台密码
- 修改 Web 端口
- 配置导入、导出
- 服务日志查看
- 一键诊断报告
- 模块服务重启
- CSRF 和后台密码校验
- 设备适配检测（Root 框架 / Android 版本 / 核心工具可用性）
- 短信正文二次验证

## 兼容性说明（v1.7.6 起：通用兼容架构）

本项目采用 **Android 通用兼容架构**：所有热点读取/修改/启动/停止/状态检测统一走 **Hotspot Compatibility Layer**（`lib/compat.sh`），能力由内置 **Binder Bridge probe 实测**（枚举 IWifiManager 方法签名、SoftApConfiguration.Builder 方法、反射 Framework 安全/频段常量），**不针对品牌/ROM/版本写死**；Web UI 按能力动态显示支持项，不支持的参数自动隐藏或禁用。

系统热点配置（Android 持久 **SoftApConfiguration**）是**唯一数据源**，系统设置与 Web 双向同步（同步级别：A=完整读写 / B=只读 / C=仅开关与状态，页面会显示当前级别）。写入一律走 Wi-Fi Framework 的 `setSoftApConfiguration()`（经内置 **Binder Bridge**，与系统设置应用同一持久化路径），`WifiConfigStore.xml` 仅在读取时作为只读兜底。

| 设备/环境 | 状态 |
|---|---|
| Xiaomi 14（houji） | 已验证（主要测试设备） |
| HyperOS 3 / Android 16 | 已验证 |
| KernelSU | 已验证 |
| Magisk / APatch | 未完整测试 |
| 其他已 Root 安卓设备 | 按系统能力自动降级，欢迎反馈测试结果 |
| Pixel / AOSP | 架构支持，未验证 |
| Samsung One UI / OPPO / vivo | 架构支持，未验证 |

其他设备必须同时满足：
- 已取得 Root 权限
- 系统提供 `cmd wifi start-softap` 和 `cmd wifi stop-softap`
- Root CGI 进程能够调用 Android 系统服务
- BusyBox 包含项目所需命令
- 系统内核支持 iptables 和相关网络统计能力
- ROM 没有额外限制 SoftAP、Binder 或后台 Root 进程
- 热点接口、IP 地址及 dumpsys 输出能够被正确识别

不同厂商 ROM 可能修改热点命令、网络接口名称、SELinux 策略、短信数据库或系统状态输出，因此其他设备可能出现部分功能不可用。

### 已知限制

- **v1.7.6 起热点配置已与系统设置合一**：网页修改的热点名称/密码/频段等经 **Binder Bridge** 调用系统 `setSoftApConfiguration(config, packageName)` 持久化（标准 AOSP 两参签名，运行时枚举兼容 OEM 变体；该接口才真正写入 `WifiApConfigStore`），系统设置页同步可见；系统设置里手动修改同样会反映到 Web。**不使用** `cmd wifi start-softap <参数>`（它只临时启动、不写系统配置），也不直接改写 `WifiConfigStore.xml`（内存配置不会随之更新、会被系统写回覆盖）。热点**开关**走系统 Tethering（`connectivity tether start/stop`，与设置应用同一路径），`cmd wifi` 仅作能力验证后的 OEM fallback。热点开启时保存会重启一次应用新配置；关闭时保存不启动、下次开启生效；写失败时热点保持原状态不掉线。
- 单 Wi-Fi 硬件不能 STA+AP 并发；普通 Wi-Fi 开启时热点可保持运行，但上游联网是否可共享给客户端取决于 ROM 路由策略（页面有检测提示）。
- 定时/保活/空闲关闭由模块 watchdog 每 15 秒轮询驱动，误差在 15 秒以内。
- 流量限额口径为热点客户端转发流量，与运营商账单口径可能有差异，仅供参考。
- 各 ROM 可能修改热点命令、接口名称、SELinux 策略或系统状态输出；不支持的参数按能力自动隐藏/禁用。

## 安装要求

- Xiaomi 14（houji）
- HyperOS 3 / Android 16
- 已解锁 Bootloader
- 已安装并正常运行 KernelSU
- 模块拥有 Root 权限
- 建议使用 Chrome 或系统 WebView 访问后台

## 安装步骤

1. 在 KernelSU 中安装模块 ZIP
2. 重启手机
3. 连接手机热点
4. 打开模块显示的管理地址
5. 首次登录后立即修改后台密码
6. 根据需要配置热点、流量、通知和自动化功能

首选管理地址为 `http://192.168.43.1:8080`。如果 ROM 不允许绑定固定别名，请使用页面或诊断报告显示的实际网关地址。

> 关闭热点后，当前通过热点连接的设备会立即断开管理页面。短信转发、PushPlus 和钉钉通知等后台服务仍会继续运行。
